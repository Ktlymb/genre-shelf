## 1. 目标与范围

### 1.1 目标

1. 登录后，录入自己读过的书。
2. **地图页**：世界地图按各国已读书数量着色；悬停国家查看作者与作品；点击书名进入详情。
3. **大中华二级地图**：华语作品按作者籍贯，细分到省级单位着色。
4. **表格页**：以表格展示全部书籍，支持筛选、排序、分组、汇总与图表分析。
5. **单人自用**：一个账号、一个书库，口令登录；多用户与分享列为未来扩展（§8.2）。

### 1.2 第一版（v1）不做

- 多用户、注册、邀请码、公开分享页，以及书友之间的关注、评论、点赞等社交功能（未来扩展，见 §8.2）
- 自动抓取书籍信息（豆瓣、ISBN 查询等）
- 多语言界面（只做中文，但文案集中存放，为以后加英文留口子）
- 原生手机 App（网页做好手机适配即可）
- 大中华以外其他国家的下级行政区地图（数据模型已预留，见 §4.6）

## 3. 技术选型

选型原则：**使用者在中国大陆，必须保证大陆网络稳定可访问**；部署简单、维护省心；数据完全由自己掌握。

| 层 | 选择 | 理由 |
|---|---|---|
| 前端框架 | Next.js（App Router）+ TypeScript | 生态成熟，一个项目同时包含页面和服务端逻辑 |
| 样式 | Tailwind CSS | 开发快，手机适配方便 |
| 数据库 | SQLite（单个数据文件）+ Drizzle ORM | 单人自用完全够用；备份就是复制一个文件；部署最简单 |
| 登录与权限 | 单个访问口令 + 签名 Cookie 会话（自行实现，不引入认证库） | 只有一个账号，不需要完整的认证框架；未登录一律拒绝，登录后可读写全部数据 |
| 托管 | 境外 VPS（香港/东京/新加坡，1 vCPU / 1 GB 内存足够）+ Docker Compose（Caddy 自动 HTTPS + Next.js，SQLite 数据文件放在持久化卷） | 大陆访问相对稳定；一台机器搞定所有组件 |
| 部署 | GitHub Actions：推送到主分支后自动构建并部署到 VPS | 我来配置，你无需手动操作服务器 |
| 静态资源 | 字体、脚本、地图数据**全部随站点自托管**；使用系统中文字体（苹方、微软雅黑、Noto Sans SC） | 不引用 Google Fonts、unpkg 等在大陆常常无法访问的境外 CDN |
| 地图 | D3-geo + d3-zoom 渲染 SVG；世界底图用 Natural Earth 1:50m admin-0，大中华二级地图用 Natural Earth admin-1（均为公有领域） | 着色、缩放、悬停完全可控 |
| 表格 | TanStack Table（无样式表格引擎）+ 自建筛选/分组/汇总层 | 要做到类 Notion 的体验，现成「大而全」的表格组件反而难改 |
| 图表 | Recharts | 够用，与 React 配合好 |
| 色彩插值 | culori（OKLab 空间插值） | 蓝→红直接按 RGB 插值会出现脏紫色，OKLab 过渡更干净 |
| 测试 | Vitest（单元）+ Playwright（端到端） | |

### 3.1 部署与大陆访问

- **为什么不用 Vercel + Supabase**：据我了解，它们的默认域名在中国大陆经常不稳定甚至无法访问，而使用者在大陆，所以不采用。
- **服务器放境外，不做大陆备案**：大陆备案需要大陆主体，且据我了解，在大陆境内提供网络地图服务还有测绘与审图方面的要求，本项目采用的开源底图并不满足（见 §14 R4）。因此网站仅本人自用，不公开推广。
- **费用（粗略估计，以实际报价为准）**：VPS 约每月 4–6 美元，域名约每年 10 美元。这是项目上线后唯一的持续开销。
- **上线前验收**：用大陆的移动、联通、电信网络分别实测访问速度；若某条线路明显不佳，更换机房或线路（数据与程序不变，只迁移服务器）。
- **忘记口令**：由我更换服务器配置中的口令哈希，不需要邮件服务。

## 4. 数据模型

### 4.1 实体关系

```
books *──* authors            （经 book_authors 关联）
  │ *──1 book_types
  │ *──1 countries
  │ *──0..1 regions           （仅当国家为「大中华地区」时有籍贯）
authors *──0..1 regions
saved_views、settings（各自独立）
countries（预设数据；含现代国家、历史国家、区域分组）
regions（预设数据：大中华 34 个省级单位）
```

只有一个用户，所以表里没有 `user_id`。

### 4.2 表结构（SQLite）

约定：布尔值用 0/1；数组与 JSON 存为 JSON 文本（SQLite 的 `json_each` 可查询）；时间用 ISO 8601 文本；启动时开启 `PRAGMA foreign_keys = ON`。

```sql
-- 应用设置（键值对）：地图两极颜色、着色模式、着色依据等
create table settings (
  key    text primary key,
  value  text not null                       -- JSON
);

-- 国家/地区（现代国家、历史国家、区域分组）
create table countries (
  code          text primary key,            -- 现代国家用 ISO 3166-1 alpha-2，如 GR；其余用自定义码，如 SU、YU、GC
  name_zh       text not null,
  name_en       text not null,
  kind          text not null check (kind in ('modern','historical','group')),
  valid_from    integer,                     -- 历史国家的存续年份，可为负数
  valid_to      integer,
  map_codes     text not null,               -- JSON 数组：在世界地图上给哪些色块着色；现代国家就是它自己
  merge_display integer not null default 0,  -- 1：世界地图上把 map_codes 合并为一个单元，使用同一颜色（见 §5.5）
  selectable    integer not null default 1,  -- 0：不出现在录书的国家下拉里
  group_code    text references countries,   -- 所属区域分组，如 CN → GC
  sort_order    integer not null default 0
);

-- 下级区域（目前只有大中华的 34 个省级单位）
create table regions (
  code        text primary key,              -- 自定义码，如 GC-AH（安徽）、GC-TW（台湾）
  group_code  text not null references countries,   -- 所属区域分组，如 GC
  name_zh     text not null,
  name_en     text not null,
  map_id      text not null,                 -- 对应二级底图中色块的编号
  sort_order  integer not null default 0
);

-- 书籍类型（预设 + 自定义，全部可编辑）
create table book_types (
  id          integer primary key autoincrement,
  code        text not null unique check (length(code) = 4 and code = upper(code)),  -- 图标上的四字母简称
  name_zh     text not null,
  bg_color    text not null,                 -- #RRGGBB
  sort_order  integer not null default 0
);                                           -- 被书籍引用的类型不可删除

-- 作者
create table authors (
  id            integer primary key autoincrement,
  name          text not null unique,
  name_original text,
  country_code  text references countries,   -- 作者的地理归属，用于录书时的默认值
  region_code   text references regions,     -- 籍贯，仅当归属为「大中华地区」
  check (region_code is null or country_code = 'GC')
);

-- 书籍
create table books (
  id            integer primary key autoincrement,        -- 书籍编号（主键）
  title         text not null,               -- 书名
  original_title text,                       -- 原著名
  country_code  text not null references countries,       -- 地图归属
  region_code   text references regions,     -- 籍贯，仅当归属为「大中华地区」；默认取第一作者的籍贯
  type_id       integer not null references book_types,
  word_count    integer check (word_count >= 0),          -- 字数，可空
  year_written  integer,                     -- 创作年份，可为负数（公元前）
  year_approx   integer not null default 0,  -- 「约」
  translators   text not null default '[]',  -- JSON 数组
  publisher     text,
  finished_on   text,                        -- 读完日期（YYYY-MM-DD）；空 = 未读完/日期不详
  status        text not null default 'finished' check (status in ('reading','finished')),
  rating        integer check (rating between 1 and 5),
  isbn          text,
  notes         text,                        -- 读后感/笔记
  created_at    text not null default (datetime('now')),
  updated_at    text not null default (datetime('now')),
  check (region_code is null or country_code = 'GC')
);

-- 书-作者关联（有序，第一位为第一作者）
create table book_authors (
  book_id    integer not null references books on delete cascade,
  author_id  integer not null references authors on delete restrict,
  position   integer not null default 0,
  primary key (book_id, author_id)
);

-- 表格视图（保存筛选/排序/分组/列显示配置）
create table saved_views (
  id        integer primary key autoincrement,
  name      text not null,
  config    text not null,                   -- JSON
  position  integer not null default 0
);
```

**索引**：`books(country_code)`、`books(region_code)`、`books(finished_on)`、`book_authors(author_id)`。

### 4.3 字段对照（对应原始需求）

| 原始字段 | 数据库字段 | 类型 | 必填 |
|---|---|---|---|
| 书籍编号（主键） | `books.id` | 自增整数 | 自动 |
| （补充）书名 | `title` | 文本 | 是 |
| 作者 | `book_authors` → `authors` | 多对多 | 是，至少一位 |
| 国家 | `country_code` | 外键 | 是（默认取第一作者的归属） |
| （补充）籍贯 | `region_code` | 外键 | 否，仅「大中华地区」适用 |
| 字数 | `word_count` | 整数 | 否 |
| 书籍类型 | `type_id` | 外键（单选） | 是 |
| 创作年份 | `year_written` + `year_approx` | 整数 + 布尔 | 否 |
| 译者 | `translators` | 文本数组 | 否 |
| 出版社 | `publisher` | 文本 | 否 |
| 读完日期 | `finished_on` | 日期 | 否 |
| 原著名 | `original_title` | 文本 | 否 |
| （补充）评分、笔记、ISBN、状态 | `rating`、`notes`、`isbn`、`status` | | 否 |

### 4.5 历史国家与已消失的政权（D7、D10）

**问题**：用户读过「南斯拉夫联盟」的书，但地图上没有这个国家的色块；奥匈帝国、波兰立陶宛联邦等同理。

**做法**：`countries` 表里同时存放现代国家与历史国家。每本书的 `country_code` 记录**历史上真实的归属**（不改写史实），`map_codes` 字段说明它在今天的地图上给哪些色块着色（规则见 §5.5 规则 B）。所有已消失的政权都用同一机制，没有特例。

**两条原则**

1. **`map_codes` 是「着色范围」，不是完整疆域。** 对跨越许多民族的大帝国，我只列了核心地区。否则一本卡夫卡会让十几个国家同时加一本，地图就失真了。预设范围是我的判断，可在设置页随时调整。
2. **录书指引：优先选现代国家。** 只有当作者或作品的归属确实横跨多个今天的国家、或者你想保留历史身份时，才选历史国家。例如：托尔斯泰直接选「俄罗斯」；卡夫卡则可选「奥匈帝国」。

**预设条目**（可在设置页追加）：

|---|---|---|---|
| `YU` | 南斯拉夫联盟 | 1992–2003 | RS 塞尔维亚、ME 黑山、XK 科索沃 |

| `CSK` | 塞尔维亚和黑山 | 2003–2006 | RS、ME、XK |
| `SU` | 苏联 | 1922–1991 | RU、UA、BY、MD、LT、LV、EE、GE、AM、AZ、KZ、UZ、TM、KG、TJ |
| `CS` | 捷克斯洛伐克 | 1918–1992 | CZ、SK |
| `DDR` | 东德 | 1949–1990 | DE |
| `FRG` | 西德 | 1949–1990 | DE |
| `AH` | 奥匈帝国 | 1867–1918 | AT、HU、CZ、SK、SI、HR、BA |
| `AUE` | 奥地利帝国 | 1804–1867 | AT、HU、CZ、SK、SI、HR |
| `PLC` | 波兰立陶宛联邦 | 1569–1795 | PL、LT、BY、UA |
| `HRE` | 神圣罗马帝国 | 962–1806 | DE、AT、CZ |

| `AEG` | 古埃及 | 公元前 3100–前 30 | EG |

- **中国历代王朝不需要单独条目**：华语作品统一归入「大中华地区」（§4.6），朝代体现在「创作年份」字段里即可。
- 同一个色块被多个条目覆盖时（例如塞尔维亚同时被 `YU`、`YUS`、现代塞尔维亚覆盖），数量取**去重后的书数**，不会重复计算。
- **设置页** `/settings/countries`：可新增、修改历史国家条目（名称、存续年份、着色范围多选、是否合并显示），不需要改代码。

> `YU` 与 `YUS` 两个条目都启用：具体某本书属于哪个时期，由录书时选择。**`SU` 未读**：条目保留备用，但在没有书之前，地图上不会有任何东西为它着色。

### 4.6 大中华地区与籍贯（D8）

**设计意图**：「大中华地区」是一个按语言与文化划分的**阅读区域**，用来承载华语作品，名称与图示都不对任何政治归属表态。

**区域分组条目**

| code | 名称 | kind | `map_codes` | `merge_display` | `selectable` |
|---|---|---|---|---|---|
| `GC` | 大中华地区 | group | CN、TW、HK、MO | **true** | true |
| `CN`、`TW`、`HK`、`MO` | （地图色块） | modern | 各自 | false | **false** |

- `CN/TW/HK/MO` 保留在 `countries` 表里，仅用来通过 §5.1 的「色块一致性检查」，并通过 `group_code = 'GC'` 指向所属分组。它们**不出现在录书的国家下拉里**，录书时只能选「大中华地区」。
- 世界地图上，这四个色块合并显示为一个单元（见 §5.5）。

**籍贯（`regions` 表，34 项）**

预设为大中华的省级单位，按拼音或常用顺序排列，显示简称，不附加行政级别后缀：

> 北京、天津、河北、山西、内蒙古、辽宁、吉林、黑龙江、上海、江苏、浙江、安徽、福建、江西、山东、河南、湖北、湖南、广东、广西、海南、重庆、四川、贵州、云南、西藏、陕西、甘肃、青海、宁夏、新疆、台湾、香港、澳门

- 籍贯码用自定义的 `GC-xx` 体系（如 `GC-AH` 安徽、`GC-TW` 台湾），不借用任何单一标准的行政级别分类。
- 籍贯**可选**。没填籍贯的书只计入「大中华地区」总数，不出现在二级地图的省级着色里，但二级地图上有「未填写籍贯 N 本」的提示（见 §5.7）。

**归属规则**

- 作者表单里选「国家/地区归属」。选「大中华地区」时，出现「籍贯」选择器。
- **华语作家以籍贯判断归属。** 如果某位作家想按国籍计入另一个国家（如入籍他国的作家），在作者表单里直接选那个国家即可；这是用户的手动选择，系统不做自动判断。
- 书籍的 `country_code` 与 `region_code` 默认取第一作者的值，可对单本书手动覆盖。
- 约束：只有归属为 `GC` 时才允许填写籍贯。

**扩展性**：`regions.group_code` 允许以后为其他国家添加下级区域（如日本的都道府县），v1 不做。

## 5. 地图页

### 5.1 世界地图渲染

- 底图：Natural Earth 1:50m admin-0，构建脚本 `scripts/build-map.ts` 转为简化的 TopoJSON，每个多边形带统一的 `code` 属性（ISO alpha-2；科索沃为 `XK`）。
- 构建时有一致性检查：`countries` 表里每个现代国家都有对应色块；每个色块都有对应的 `countries` 条目。缺一即报错。
- 投影：Natural Earth 投影，初始视图为全世界。
- 缩放：滚轮 / 双指缩放，范围 1×–40×，可拖动；右下角有「＋ − 复位」按钮；缩放时描边线宽反向补偿，保持视觉粗细不变。
- **微型国家**：面积过小、在地图上看不见的国家和地区（新加坡、马耳他、梵蒂冈、摩纳哥、列支敦士登、圣马力诺、安道尔、马尔代夫、各小岛国等）以**小圆点标记**叠加显示，同样着色、可悬停、可点击。放大到一定倍数后圆点隐去，改显真实边界。
- 无书的国家：中性灰 `#E4E4E4`。
- **界面中不出现任何国旗**（D9）。国家一律显示中文名称。

### 5.2 着色算法（解决极端值问题）

要求：一个国家读了 50 本、其余都是几本时，其余国家之间仍要有明显色差。

**默认模式：等级映射（rank mapping）**

```
输入：各地图单元的书数 n_i（仅统计 n_i > 0 的单元）
1. 取所有不同的数值，升序排列：v_1 < v_2 < … < v_k
2. 若 k == 1：所有单元 t = 0.5
   否则，数值 v_j 的 t = (j - 1) / (k - 1)        // 最少 → 0（纯蓝），最多 → 1（纯红）
3. 颜色 = 在 OKLab 空间里，对 [低端色, 高端色] 按 t 插值
```

例：数值为 {1, 2, 3, 5, 50} → t 依次为 0、0.25、0.5、0.75、1。50 本只占最红的一档，不会把其他国家压成同一种颜色。相同本数的单元颜色相同。

**世界地图与大中华二级地图分别独立计算**：二级地图只在各省级单位之间比较，不受世界地图上其他国家数量影响。

**可选模式**（用户在地图页的设置里切换）：

| 模式 | 公式 | 适用 |
|---|---|---|
| 等级映射（默认） | 如上 | 分布极不均匀 |
| 对数 | `t = log(n) / log(max)` | 想让颜色仍大致反映数量比例 |
| 线性 | `t = (n - min) / (max - min)` | 数据均匀时；极端值下会失效，因此作为选项而非默认 |

**颜色设置**：
- 低端色默认蓝 `#3B6FB6`，高端色默认红 `#C8372D`，两者用户都可改。
- 可选「中间过渡色」（默认关闭；开启后做三色渐变，如蓝 → 浅灰 → 红）。
- 设置保存在 `settings` 表，下次打开保持。

**图例**：地图角落显示色带；色带上标出各档对应的本数（等级映射下是「几本 ↔ 哪种颜色」的离散色块，而不是连续刻度）。

### 5.3 悬停面板

**交互设计**（这里与"鼠标悬停"原始描述略有调整，原因见下）：

- 桌面端：鼠标悬停国家约 150ms 后，在右侧（窄屏在底部）弹出面板。鼠标可以移入面板，面板不会消失；点击国家则**固定**面板，再点空白处取消固定。
- 手机/平板：没有悬停，**点按**国家即固定显示面板。
- 调整原因：如果面板只跟随鼠标出现，鼠标一移开就消失，用户就没法点击里面的书名或折叠作者了。

**面板内容**（竖向列表）：

```
希腊 · 已读 7 本 · 4 位作者
▾ 荷马 (3)
    [EPIC] 奥德赛
    [EPIC] 伊利亚特
    [HIST] ……
▸ 索福克勒斯 (2)
▸ ……
```

- 面板头部只有文字名称，没有国旗。
- 作者可折叠，默认展开前 3 位，其余收起；顶部提供「全部展开 / 全部折叠」。
- 作者按**该单元已读书数**降序；同数量时按作者名排序。作者下的书按读完日期倒序。
- 一本书有多位作者时，在每位作者名下都出现（面板头部的总数按书去重）。
- 书名左侧是类型图标：圆角矩形、该类型背景色、白色四字母简称（如 `EPIC`，棕底）。
- 点击书名 → 书籍详情页 `/books/:id`。
- 历史国家的书，在书名后附小标签，如「南斯拉夫联盟」。
- 书很多的国家：面板内部滚动，最大高度不超过视口。
- **「大中华地区」单元的面板**头部多一个按钮「查看省级分布」，进入二级地图（§5.7）。

### 5.4 国家选择

- 悬停/点按时，该单元高亮描边。
- 页面顶部提供「搜索国家」输入框（中文名/英文名），选中后地图自动缩放定位到该单元——这是小国难以点中时的备用入口。

### 5.5 区域合并与历史国家的地图规则

地图上的一个**显示单元**有两种来源，规则不同：

**规则 A：合并显示（`merge_display = true`，用于「大中华地区」）**

- `map_codes` 里的所有色块视为**同一个单元**：同一种颜色、同时高亮、同一个悬停面板、同一个名称。单元内部的边界线隐藏（不要求几何上做并集，只是共享样式与事件）。
- 单元的数量 = 直接归属于该条目的书的数量。
- 被合并的色块（CN、TW、HK、MO）不再单独着色，也不单独统计。

**规则 B：领土归属计数（`merge_display = false` 的历史国家）**

- 一本书归属历史国家时，它计入该条目 `map_codes` 里**每一个**现代色块。
- 每个色块的数量 = 归属到任何覆盖它的条目的书的**去重总数**。
- 悬停面板里，该色块下的书按作者分组，来自历史国家的书带上历史国家标签。

示例：用户读了 4 本南联盟的书、2 本塞尔维亚的书。塞尔维亚色块显示 6 本；黑山与科索沃色块各显示 4 本。

**已知局限**：规则 B 用 3 个色块各显示 4 本，会让人以为黑山单独读了 4 本。如果觉得不直观，可以把某个历史条目的 `merge_display` 改为 `true`，让它按规则 A 合并显示（名称如「南斯拉夫联盟（今塞尔维亚、黑山、科索沃）」）。这是数据层的修改，**不需要改代码**。v1 默认保留规则 B。

### 5.6 边界与命名

- 世界地图上，「大中华地区」合并为单一单元，因此世界地图不再需要对台湾、香港、澳门做独立的归属表态。
- 其他地区（科索沃、克里米亚、西撒哈拉、克什米尔等）的边界与命名，采用 Natural Earth 的默认处理。每个色块都映射到 `countries` 表，因此**名称与归属可通过数据修改，不需要改代码**。
- 大中华二级地图的边界、名称处理见 §5.7 与 §14 Q3。

### 5.7 大中华二级地图（省级）

路由：`/map/gc`。入口：①世界地图上「大中华地区」面板的「查看省级分布」按钮；②顶部导航「地图」下的切换标签。

- **底图**：Natural Earth admin-1，覆盖 §4.6 的 34 个单位，由 `scripts/build-map.ts` 生成并做一致性检查：`regions` 表每一项都有对应色块，每个色块都有对应的 `regions` 条目。
- **着色**：按 `region_code` 统计各单位的书数，使用 §5.2 同样的算法（只在 34 个单位内部比较）。无书的单位为中性灰。
- **悬停/点按面板**：与 §5.3 完全一致——作者可折叠、按本数排序、书名带类型图标、点击进入详情。头部显示单位名称，如「安徽 · 已读 6 本」。
- **未填写籍贯**：地图一角显示一个提示条「未填写籍贯：N 本」，点击打开列表，列出这些书，方便补填。
- **香港、澳门**面积小，沿用 §5.1 的微型标记；可缩放，与世界地图一致。
- 顶部有「← 返回世界地图」。
- 名称显示为不带行政级别后缀的简称（安徽、台湾、香港……）。

### 7.3 CSV 导入导出

- 表头使用中文，与 §4.3 字段名一致：`书名, 原著名, 作者, 国家, 籍贯, 字数, 书籍类型, 创作年份, 译者, 出版社, 读完日期`（可选：`评分, ISBN, 笔记`）。
- 多位作者/译者用 `;` 分隔。
- 国家按中文名匹配 `countries`；类型按名称或简称匹配；籍贯按 `regions` 的中文名匹配。
- **便利规则**：若「国家」为空而「籍贯」能识别，则国家自动设为「大中华地区」；若「国家」填写了「台湾」「香港」「澳门」「中国」「中国大陆」「大中华」，导入时统一归入「大中华地区」，并在能确定时自动补全籍贯（台湾、香港、澳门）。这些转换在预览中明确标出，用户可逐行修改。
- 导入先做**预览与校验**：显示每行的识别结果，错误行（国家无法识别、日期格式错误等）高亮并说明原因；用户确认后才写入。
- 不存在的作者自动新建；已存在则复用。
- 文件编码兼容 UTF-8（含 BOM，即 Excel 另存的 CSV）。大小上限 2 MB。

## 8. 访问与安全

### 8.1 登录

- **单账号，只有一个「访问口令」**：没有注册，没有用户名，没有邀请码。
- 口令的哈希保存在服务器配置（环境变量）里，不入库，也不进代码仓库。
- 登录后发放签名 Cookie（HttpOnly、Secure、SameSite=Lax），有效期 30 天；设置页有「退出登录」。
- 登录失败限流：同一 IP 连续输错 5 次后锁定 15 分钟。
- 未登录访问任何页面都跳转到 `/login`，访问任何接口都返回 401。
- 忘记口令或怀疑泄露：由我更换服务器配置中的口令哈希与会话密钥，所有登录自动失效。

### 8.2 未来扩展（不在本版范围）

多用户注册、邀请码、公开分享页都可以以后再加。迁移路径：`books`、`authors`、`saved_views`、`settings` 各加一列 `user_id`，把现有数据全部归给第一个用户；数据库可按需从 SQLite 迁到 PostgreSQL。本版**刻意不预留**这些复杂度。

## 13. 验收要点

1. 录入读过的书后，对应国家在地图上变色，且颜色随数量按 §5.2 规则变化。
2. 构造测试数据：一个国家 50 本，其余国家 1、2、3、4 本。后者之间在地图上颜色肉眼可分。
3. 悬停（桌面）或点按（手机）国家，面板列出作者与书；作者可折叠；顺序按本数降序；类型图标颜色与简称正确；点击书名进入详情页。
4. 地图可缩放到能点中卢森堡、新加坡、梵蒂冈等小国。
5. 录入一本归属「南斯拉夫联盟」的书，塞尔维亚、黑山、科索沃均出现颜色；苏联在无书时没有任何色块被着色。
6. 录入多本大中华作品，世界地图上大陆、台湾、香港、澳门**同一颜色、同时高亮、同一个面板**；国家下拉里**没有**单独的中国/台湾/香港/澳门选项。
7. 界面任何位置（面板、下拉、图例、详情页）**不出现国旗**。
8. 给大中华作品填写籍贯后，二级地图上对应省级单位变色；颜色在 34 个单位内部独立按 §5.2 计算；未填籍贯的书出现在「未填写籍贯」提示里，补填后消失。
9. 表格可按任意字段（含籍贯）筛选/排序/分组，汇总行正确；保存的视图刷新后仍在。
10. 未登录时，任何页面与接口都无法访问（页面跳转登录页，接口返回 401）；口令连续输错 5 次后被临时锁定。
11. 导入 100 行 CSV，错误行被指出；国家填「台湾」的行被归并到大中华并补全籍贯，预览中有标注；确认后正确写入。

## 1. 目标与范围

### 1.1 目标

1. 录入自己读过的书。
2. **地图页**：世界地图按各国已读书数量着色；悬停国家查看作者与作品；点击书名进入详情。
3. **大中华二级地图**：华语作品按作者籍贯，细分到省级单位着色。
4. **表格页**：以表格展示全部书籍，支持筛选、排序、分组、汇总与图表分析。
5. **单人自用、单机可用**：一个书库，数据保存在自己的设备上；电脑（Windows）与手机（安卓）都能用，通过备份文件同步。

### 1.2 第一版（v1）不做

- 服务器、账号、登录、注册、公开分享
- 自动云同步（阶段二，视使用体验再决定，见 §3.2）
- 自动抓取书籍信息（豆瓣、ISBN 查询等）
- 多语言界面（只做中文，但文案集中存放，为以后加英文留口子）
- 原生手机 App（网页做好手机适配即可）
- 大中华以外其他国家的下级行政区地图（数据模型已预留，见 §4.6）

## 3. 技术选型

选型原则：**单人使用、大陆可用、离线可用、零费用、数据掌握在自己手里。**

| 层 | 选择 | 理由 |
|---|---|---|
| 形态 | 单页应用，构建成**单个 HTML 文件**（`genre-shelf.html`，vite-plugin-singlefile） | 双击即可打开，也可原样放到任何静态空间 |
| 框架 | React + TypeScript + Vite | 生态成熟 |
| 样式 | Tailwind CSS（编译后内联） | 开发快，手机适配方便 |
| 路由 | 哈希路由（`#/map`、`#/table`…） | 单文件没有服务器，无法分发页面路径 |
| 数据存储 | IndexedDB（Dexie 封装） | 浏览器内置的本地数据库，容量足够；存的是普通 JSON 对象 |
| 文件存档 | 电脑上的 Chrome/Edge：File System Access API 自动写入用户选定的数据文件；其他浏览器：手动导出 | 数据不只依赖浏览器内部存储（见 §8） |
| 地图 | D3-geo + d3-zoom 渲染 SVG；世界底图用 Natural Earth 1:50m admin-0，大中华二级地图用 Natural Earth admin-1（其中台湾、香港、澳门取自 admin-0，见 §15.2；均为公有领域），数据内联进文件 | 着色、缩放、悬停完全可控；离线可用 |
| 表格 | TanStack Table（无样式表格引擎）+ 自建筛选/分组/汇总层 | 要做到类 Notion 的体验，现成「大而全」的表格组件反而难改 |
| 图表 | Recharts | 够用，与 React 配合好 |
| 色彩插值 | culori（OKLab 空间插值） | 蓝→红直接按 RGB 插值会出现脏紫色，OKLab 过渡更干净 |
| 字体与资源 | 使用系统中文字体（微软雅黑、苹方、Noto Sans SC）；所有资源内联，**运行时不发起任何网络请求** | 离线可用；不依赖在大陆常常无法访问的境外服务 |
| ID | ULID（带时间顺序的唯一 ID） | 两台设备各自新增数据，合并时不会冲突 |
| 测试 | Vitest（单元）+ Playwright（打开构建出的单文件做端到端测试） | |
| 构建与分发 | GitHub Actions 每次提交自动构建单文件并保存为构建产物；定稿版本发布到 GitHub Release | GitHub 在大陆访问不稳定，交付给使用者时另通过微信或网盘传文件 |

### 3.1 设备与使用方式

| 设备 | 怎么用 | 备注 |
|---|---|---|
| Windows 电脑 | 用 **Chrome 或 Edge** 打开 `genre-shelf.html` | 推荐，支持「自动写入数据文件」 |
| 安卓手机 | 用 Chrome 打开同一个文件（文件管理器、微信/网盘下载后选择「用 Chrome 打开」） | 安卓版 Chrome 不支持自动写入文件，只能导出/导入备份。**能否直接打开本地文件取决于具体手机与文件管理器，M0 先实测**（§14 Q10） |

**手机打开不了本地文件时的备选**：把同一个文件放到一个静态网址上，手机用网址打开并「添加到主屏幕」。这需要一个域名（约每年 10 美元）并实测大陆访问速度；数据仍然保存在各设备的浏览器里，不上传到任何地方。

### 3.2 多设备同步

- **v1：手动同步。** 电脑上「导出完整备份」→ 通过微信文件传输助手或网盘发到手机 → 手机上「导入」并选择「合并」。反方向同理。合并规则见 §7.4，不会产生重复，也不会覆盖较新的修改。
- **阶段二（可选）：云同步。** 如果手动搬运太烦，再加一个同步功能（例如 Cloudflare Worker + D1，或自有服务器）。**此时才需要域名并实测大陆访问。** 数据层从 v1 起就预留了所需字段（ULID、`updated_at`、`deleted_at`），不需要推翻重来。

### 3.3 为什么大陆访问和备案问题不存在

应用是本机运行的文件，没有任何网站对外提供服务，也不连接任何服务器。所以不存在「大陆能否打开」的问题，也不涉及网站备案；地图只在本人设备上显示，不是对外的网络地图服务。（若以后选择放到静态网址或做云同步，这些问题需要重新评估，见 §14 R4。）

## 4. 数据模型

### 4.1 实体关系

```
Book *──* Author             （Book.author_ids 有序数组，第一位为第一作者）
 │ *──1 BookType
 │ *──1 Country
 │ *──0..1 Region            （仅当国家为「大中华地区」时有籍贯）
Author *──0..1 Region
SavedView、Settings（各自独立）
Country（预设数据；含现代国家、历史国家、区域分组）
Region（预设数据：大中华 34 个省级单位）
```

### 4.2 数据结构（IndexedDB，TypeScript 类型）

字段名沿用 snake_case，与本文其他章节一致。日期用 ISO 8601 文本，`finished_on` 为 `YYYY-MM-DD`。

```ts
// 应用设置（只有一条）：地图两极颜色、着色模式、着色依据等
interface Settings {
  id: 'main';
  low_color: string;                    // 默认 #3B6FB6
  high_color: string;                   // 默认 #C8372D
  mid_color?: string;                   // 可选的中间过渡色
  scale_mode: 'rank' | 'log' | 'linear';// 默认 rank
  metric: 'count' | 'words';            // 默认 count
  last_backup_at?: string;              // 上次导出备份的时间
  seed_version: number;                 // 预设数据版本，用于升级时补充新条目
  updated_at: string;                   // 合并导入时，颜色等设置取较新的一方；last_backup_at 与 seed_version 是本机状态，不随合并导入
}

// 国家/地区（现代国家、历史国家、区域分组）。预设数据随文件内置，首次打开写入 IndexedDB
interface Country {
  code: string;                         // 现代国家用 ISO 3166-1 alpha-2，如 GR；其余用自定义码，如 SU、YU、GC
  name_zh: string;
  name_en: string;
  kind: 'modern' | 'historical' | 'group';
  valid_from?: number;                  // 历史国家的存续年份，可为负数
  valid_to?: number;
  map_codes: string[];                  // 在世界地图上给哪些色块着色；现代国家就是它自己
  merge_display: boolean;               // true：世界地图上把 map_codes 合并为一个单元，使用同一颜色（见 §5.5）
  selectable: boolean;                  // false：不出现在录书的国家下拉里
  group_code?: string;                  // 所属区域分组，如 CN → GC
  sort_order: number;
  updated_at: string;                   // 预设条目用固定的早期时间；用户新增或修改的条目更新此值
  deleted_at?: string;
}

// 下级区域（目前只有大中华的 34 个省级单位）。只读预设，v1 没有编辑界面，不参与合并
interface Region {
  code: string;                         // 自定义码，如 GC-AH（安徽）、GC-TW（台湾）
  group_code: string;                   // 所属区域分组，如 GC
  name_zh: string;
  name_en: string;
  map_id: string;                       // 对应二级底图中色块的编号
  sort_order: number;
}

// 以下实体都带同步字段 id / updated_at / deleted_at（Country 以 code 为键，同样带 updated_at / deleted_at）
interface Synced {
  id: string;                           // ULID
  updated_at: string;
  deleted_at?: string;                  // 软删除：删除只打标记，保留 90 天，保证合并时删除也能传播
}

// 书籍类型（预设 + 自定义，全部可编辑；被书籍引用的类型不可删除）
interface BookType extends Synced {
  code: string;                         // 图标上的四字母简称，大写字母，唯一
  name_zh: string;
  bg_color: string;                     // #RRGGBB
  sort_order: number;
}

// 作者
interface Author extends Synced {
  name: string;                         // 唯一（忽略大小写与空白）
  name_original?: string;
  country_code?: string;                // 作者的地理归属，用于录书时的默认值
  region_code?: string;                 // 籍贯，仅当归属为「大中华地区」
}

// 书籍
interface Book extends Synced {
  title: string;                        // 书名
  original_title?: string;              // 原著名
  author_ids: string[];                 // 至少一位，有序
  country_code: string;                 // 地图归属
  region_code?: string;                 // 籍贯，仅当归属为「大中华地区」；默认取第一作者的籍贯
  type_id: string;
  word_count?: number;                  // 字数
  year_written?: number;                // 创作年份，可为负数（公元前）
  year_approx: boolean;                 // 「约」
  translators: string[];
  publisher?: string;
  finished_on?: string;                 // 读完日期；空 = 未读完/日期不详
  status: 'reading' | 'finished';       // 默认 finished
  rating?: 1 | 2 | 3 | 4 | 5;
  isbn?: string;
  notes?: string;                       // 读后感/笔记
  created_at: string;
}

// 表格视图（保存筛选/排序/分组/列显示配置）
interface SavedView extends Synced {
  name: string;
  config: unknown;                      // JSON
  position: number;
}
```

**约束（由数据层统一校验，有单元测试，不依赖数据库）**：
- `region_code` 只有在同一条记录的 `country_code === 'GC'` 时才允许填写（书籍与作者都适用）。
- `Book.author_ids` 至少一项，且指向未删除的作者。
- `BookType.code` 必须是 4 位大写字母且唯一；`Country.code`、`Region.code` 唯一。
- 作者被未删除的书籍引用时，不允许删除。
- **书籍编号**（界面上的「#N」）**不存储**，由数据层按（`created_at`，`id`）顺序对未删除的书籍从 1 起编号。这样电脑与手机合并后，同一本书的编号总是一致。代价是删除一本书后，其后书籍的编号会前移；真正稳定的主键是 `id`。

**预设数据的升级**：每次发布新版文件时，`seed_version` 增加；应用启动发现版本变大，只**补充**本机缺少的预设国家、区域、类型，不覆盖用户已改动或已软删除的条目。

**索引**：`Book.country_code`、`Book.region_code`、`Book.finished_on`、`Book.updated_at`。

### 4.3 字段对照（对应原始需求）

| 原始字段 | 数据字段 | 类型 | 必填 |
|---|---|---|---|
| 书籍编号（主键） | `Book.id`（ULID，真正的主键）；界面显示的「#N」由数据层派生，不存储（§4.2） | 文本 | 自动 |
| （补充）书名 | `title` | 文本 | 是 |
| 作者 | `Book.author_ids` → `Author` | 有序引用数组 | 是，至少一位 |
| 国家 | `country_code` | 引用 `Country.code` | 是（默认取第一作者的归属） |
| （补充）籍贯 | `region_code` | 引用 `Region.code` | 否，仅「大中华地区」适用 |
| 字数 | `word_count` | 整数 | 否 |
| 书籍类型 | `type_id` | 引用 `BookType.id`（单选） | 是 |
| 创作年份 | `year_written` + `year_approx` | 整数 + 布尔 | 否 |
| 译者 | `translators` | 文本数组 | 否 |
| 出版社 | `publisher` | 文本 | 否 |
| 读完日期 | `finished_on` | 日期 | 否 |
| 原著名 | `original_title` | 文本 | 否 |
| （补充）评分、笔记、ISBN、状态 | `rating`、`notes`、`isbn`、`status` | | 否 |

### 4.5 历史国家与已消失的政权（D7、D10）

**问题**：用户读过「南斯拉夫联盟」的书，但地图上没有这个国家的色块；奥匈帝国、波兰立陶宛联邦等同理。

**做法**：`countries` 表里同时存放现代国家与历史国家。每本书的 `country_code` 记录**历史上真实的归属**（不改写史实），`map_codes` 字段说明它在今天的地图上给哪些色块着色（规则见 §5.5 规则 B）。所有已消失的政权都用同一机制，没有特例。

**两条原则**

1. **`map_codes` 是「着色范围」，不是完整疆域。** 对跨越许多民族的大帝国，只列核心地区，否则一本卡夫卡会让十几个国家同时加一本，地图就失真了。预设范围是规格书编写方的判断，可在设置页随时调整。
2. **录书指引：优先选现代国家。** 只有当作者或作品的归属确实横跨多个今天的国家、或者想保留历史身份时，才选历史国家。例如：托尔斯泰直接选「俄罗斯」；卡夫卡则可选「奥匈帝国」。

### 4.6 大中华地区与籍贯（D8）

**设计意图**：「大中华地区」是一个按语言与文化划分的**阅读区域**，用来承载华语作品，名称与图示都不对任何政治归属表态。

**区域分组条目**

| code | 名称 | kind | `map_codes` | `merge_display` | `selectable` |
|---|---|---|---|---|---|
| `GC` | 大中华地区 | group | CN、TW、HK、MO | **true** | true |
| `CN`、`TW`、`HK`、`MO` | （地图色块） | modern | 各自 | false | **false** |

- `CN/TW/HK/MO` 保留在 `countries` 表里，仅用来通过 §5.1 的「色块一致性检查」，并通过 `group_code = 'GC'` 指向所属分组。它们**不出现在录书的国家下拉里**，录书时只能选「大中华地区」。
- 世界地图上，这四个色块合并显示为一个单元（见 §5.5）。

**籍贯（`regions` 表，34 项）**

预设为大中华的省级单位，按拼音或常用顺序排列，显示简称，不附加行政级别后缀：

> 北京、天津、河北、山西、内蒙古、辽宁、吉林、黑龙江、上海、江苏、浙江、安徽、福建、江西、山东、河南、湖北、湖南、广东、广西、海南、重庆、四川、贵州、云南、西藏、陕西、甘肃、青海、宁夏、新疆、台湾、香港、澳门

- 籍贯码用自定义的 `GC-xx` 体系（如 `GC-AH` 安徽、`GC-TW` 台湾），不借用任何单一标准的行政级别分类。
- 籍贯**可选**。没填籍贯的书只计入「大中华地区」总数，不出现在二级地图的省级着色里，但二级地图上有「未填写籍贯 N 本」的提示（见 §5.7）。

**归属规则**

- 作者表单里选「国家/地区归属」。选「大中华地区」时，出现「籍贯」选择器。
- **华语作家以籍贯判断归属。** 如果某位作家想按国籍计入另一个国家（如入籍他国的作家），在作者表单里直接选那个国家即可；这是用户的手动选择，系统不做自动判断。
- 书籍的 `country_code` 与 `region_code` 默认取第一作者的值，可对单本书手动覆盖。
- 约束：只有归属为 `GC` 时才允许填写籍贯。

**扩展性**：`regions.group_code` 允许以后为其他国家添加下级区域（如日本的都道府县），v1 不做。

## 5. 地图页

### 5.1 世界地图渲染

- 底图：Natural Earth 1:50m admin-0，构建脚本 `scripts/build-map.ts` 转为简化的 TopoJSON，每个多边形带统一的 `code` 属性（ISO alpha-2；科索沃为 `XK`）。
- 构建时有一致性检查：`countries` 表里每个现代国家都有对应色块；每个色块都有对应的 `countries` 条目。缺一即报错。
- 投影：Natural Earth 投影，初始视图为全世界。
- 缩放：滚轮 / 双指缩放，范围 1×–40×，可拖动；右下角有「＋ − 复位」按钮；缩放时描边线宽反向补偿，保持视觉粗细不变。
- **微型国家**：面积过小、在地图上看不见的国家和地区（新加坡、马耳他、梵蒂冈、摩纳哥、列支敦士登、圣马力诺、安道尔、马尔代夫、各小岛国等）以**小圆点标记**叠加显示，同样着色、可悬停、可点击。放大到一定倍数后圆点隐去，改显真实边界。
- 无书的国家：中性灰 `#E4E4E4`。
- **界面中不出现任何国旗**（D9）。国家一律显示中文名称。

### 5.2 着色算法（解决极端值问题）

要求：一个国家读了 50 本、其余都是几本时，其余国家之间仍要有明显色差。

**默认模式：等级映射（rank mapping）**

```
输入：各地图单元的书数 n_i（仅统计 n_i > 0 的单元）
1. 取所有不同的数值，升序排列：v_1 < v_2 < … < v_k
2. 若 k == 1：所有单元 t = 0.5
   否则，数值 v_j 的 t = (j - 1) / (k - 1)        // 最少 → 0（纯蓝），最多 → 1（纯红）
3. 颜色 = 在 OKLab 空间里，对 [低端色, 高端色] 按 t 插值
```

例：数值为 {1, 2, 3, 5, 50} → t 依次为 0、0.25、0.5、0.75、1。50 本只占最红的一档，不会把其他国家压成同一种颜色。相同本数的单元颜色相同。

**世界地图与大中华二级地图分别独立计算**：二级地图只在各省级单位之间比较，不受世界地图上其他国家数量影响。

**可选模式**（用户在地图页的设置里切换）：

| 模式 | 公式 | 适用 |
|---|---|---|
| 等级映射（默认） | 如上 | 分布极不均匀 |
| 对数 | `t = log(n) / log(max)` | 想让颜色仍大致反映数量比例 |
| 线性 | `t = (n - min) / (max - min)` | 数据均匀时；极端值下会失效，因此作为选项而非默认 |

**着色依据（A3）**：默认按「本数」统计各单元的 n_i；可在地图页设置里切换为「字数」（各单元已读书籍的字数之和，字数为空的书按 0 计）。设置保存在 `Settings.metric`。

**颜色设置**：
- 低端色默认蓝 `#3B6FB6`，高端色默认红 `#C8372D`，两者用户都可改。
- 可选「中间过渡色」（默认关闭；开启后做三色渐变，如蓝 → 浅灰 → 红）。
- 设置保存在 `Settings`，下次打开保持。

**图例**：地图角落显示色带；色带上标出各档对应的本数（等级映射下是「几本 ↔ 哪种颜色」的离散色块，而不是连续刻度）。

### 5.3 悬停面板

**交互设计**（这里与"鼠标悬停"原始描述略有调整，原因见下）：

- 桌面端：鼠标悬停国家约 150ms 后，在右侧（窄屏在底部）弹出面板。鼠标可以移入面板，面板不会消失；点击国家则**固定**面板，再点空白处取消固定。
- 手机/平板：没有悬停，**点按**国家即固定显示面板。
- 调整原因：如果面板只跟随鼠标出现，鼠标一移开就消失，用户就没法点击里面的书名或折叠作者了。

**面板内容**（竖向列表）：

```
希腊 · 已读 7 本 · 4 位作者
▾ 荷马 (3)
    [EPIC] 奥德赛
    [EPIC] 伊利亚特
    [HIST] ……
▸ 索福克勒斯 (2)
▸ ……
```

- 面板头部只有文字名称，没有国旗。
- 作者可折叠，默认展开前 3 位，其余收起；顶部提供「全部展开 / 全部折叠」。
- 作者按**该单元已读书数**降序；同数量时按作者名排序。作者下的书按读完日期倒序。
- 一本书有多位作者时，在每位作者名下都出现（面板头部的总数按书去重）。
- 书名左侧是类型图标：圆角矩形、该类型背景色、白色四字母简称（如 `EPIC`，棕底）。
- 点击书名 → 书籍详情页 `/books/:id`。
- 历史国家的书，在书名后附小标签，如「南斯拉夫联盟」。
- 书很多的国家：面板内部滚动，最大高度不超过视口。
- **「大中华地区」单元的面板**头部多一个按钮「查看省级分布」，进入二级地图（§5.7）。

### 5.4 国家选择

- 悬停/点按时，该单元高亮描边。
- 页面顶部提供「搜索国家」输入框（中文名/英文名），选中后地图自动缩放定位到该单元——这是小国难以点中时的备用入口。

### 5.5 区域合并与历史国家的地图规则

地图上的一个**显示单元**有两种来源，规则不同：

**规则 A：合并显示（`merge_display = true`，用于「大中华地区」）**

- `map_codes` 里的所有色块视为**同一个单元**：同一种颜色、同时高亮、同一个悬停面板、同一个名称。单元内部的边界线隐藏（不要求几何上做并集，只是共享样式与事件）。
- 单元的数量 = 直接归属于该条目的书的数量。
- 被合并的色块（CN、TW、HK、MO）不再单独着色，也不单独统计。
- **约束**：开启合并显示的条目，其成员色块不得同时属于其他显示单元，也不得被其他条目的 `map_codes` 覆盖。目前只有 `GC` 满足；校验写在数据层，并有单元测试。

**规则 B：领土归属计数（`merge_display = false` 的条目，包括历史国家与现代国家；现代国家的 `map_codes` 就是它自己）**

- 一本书归属历史国家时，它计入该条目 `map_codes` 里**每一个**现代色块。
- 每个色块的数量 = 归属到任何覆盖它的条目的书的**去重总数**。
- 悬停面板里，该色块下的书按作者分组，来自历史国家的书带上历史国家标签。

示例：用户读了 4 本南联盟的书、2 本塞尔维亚的书。塞尔维亚色块显示 6 本；黑山与科索沃色块各显示 4 本。

**已知局限**：规则 B 用 3 个色块各显示 4 本，会让人以为黑山单独读了 4 本。历史国家与现代国家的色块必然重叠（塞尔维亚同时被 `YU`、`YUS`、`RS` 覆盖），所以**不能**简单地把历史国家改成合并显示，那会吞掉现代国家自己的计数。若将来觉得不直观，需要另行设计重叠处理（例如在面板里分开显示「本国」与「历史归属」来源），v1 不做。

### 5.6 边界与命名

- 世界地图上，「大中华地区」合并为单一单元，因此世界地图不再需要对台湾、香港、澳门做独立的归属表态。
- 其他地区（科索沃、克里米亚、西撒哈拉、克什米尔等）的边界与命名，采用 Natural Earth 的默认处理。每个色块都映射到 `countries` 表，因此**名称与归属可通过数据修改，不需要改代码**。
- 大中华二级地图的边界、名称处理见 §5.7 与 §14 Q3。

### 5.7 大中华二级地图（省级）

路由：`/map/gc`。入口：①世界地图上「大中华地区」面板的「查看省级分布」按钮；②顶部导航「地图」下的切换标签。

- **底图**：Natural Earth，覆盖 §4.6 的 34 个单位（31 个来自 admin-1，台湾、香港、澳门来自 admin-0，见 §15.2），由 `scripts/build-map.ts` 生成并做一致性检查：`regions` 表每一项都有对应色块，每个色块都有对应的 `regions` 条目。
- **着色**：按 `region_code` 统计各单位的书数，使用 §5.2 同样的算法（只在 34 个单位内部比较）。无书的单位为中性灰。
- **悬停/点按面板**：与 §5.3 完全一致——作者可折叠、按本数排序、书名带类型图标、点击进入详情。头部显示单位名称，如「安徽 · 已读 6 本」。
- **未填写籍贯**：地图一角显示一个提示条「未填写籍贯：N 本」，点击打开列表，列出这些书，方便补填。
- **香港、澳门**面积小，沿用 §5.1 的微型标记；可缩放，与世界地图一致。
- 顶部有「← 返回世界地图」。
- 名称显示为不带行政级别后缀的简称（安徽、台湾、香港……）。

## 7. 表格页（类 Notion）

页面 `/table`，数据与地图页同源。

### 7.1 视图能力

| 能力 | 规格 |
|---|---|
| 列显示 | 每列可显示/隐藏、拖动调整顺序和宽度 |
| 排序 | 多列排序，可拖动调整优先级 |
| 筛选 | 条件构建器：「字段 + 运算符 + 值」，多条件之间支持「且 / 或」。运算符按字段类型提供：文本（包含、等于、为空…）、数字（>、<、介于…）、日期（早于、晚于、本年、最近 N 天…）、选择类（是、不是、任一） |

| 汇总行 | 每列底部可选聚合方式：计数、非空计数、去重计数、求和、平均、最小、最大、中位数 |
| 搜索 | 顶部关键词搜索（书名、原著名、作者、译者、出版社、笔记） |
| 已保存视图 | 将当前配置（列、排序、筛选、分组、汇总）存为命名视图，顶部标签页切换 |

| 导入导出 | 导出当前视图为 CSV；导入见 §7.3 |

数据量预期：单用户最多几千行。v1 在浏览器端完成全部筛选/排序/分组，不做服务端分页。

### 7.2 数据分析面板 `/table/analysis`

图表均响应当前筛选条件：

1. 每年读书数量（按读完日期）
2. 每年阅读字数；累计字数折线
3. 各类型占比
4. 各国家/地区 Top 20（按书籍自身的国家归属统计，历史国家单独列出，不做 §5.5 的领土展开）
5. **大中华各省级单位分布**（按籍贯，条形图，含「未填写」一栏）
6. 作者 Top 20（按本数）
7. 作品创作年代分布（按世纪分桶）
8. 评分分布
9. 摘要卡片：总书数、总字数、涉及国家数、涉及作者数、平均每本字数、最长/最短书

### 7.3 CSV 导入导出

- 表头使用中文，与 §4.3 字段名一致：`书名, 原著名, 作者, 国家, 籍贯, 字数, 书籍类型, 创作年份, 译者, 出版社, 读完日期`（可选：`评分, ISBN, 笔记`）。
- 多位作者/译者用 `;` 分隔。
- 国家按中文名匹配 `countries`；类型按名称或简称匹配；籍贯按 `regions` 的中文名匹配。
- **便利规则**：若「国家」为空而「籍贯」能识别，则国家自动设为「大中华地区」；若「国家」填写了「台湾」「香港」「澳门」「中国」「中国大陆」「大中华」，导入时统一归入「大中华地区」，并在能确定时自动补全籍贯（台湾、香港、澳门）。这些转换在预览中明确标出，用户可逐行修改。
- 导入先做**预览与校验**：显示每行的识别结果，错误行（国家无法识别、日期格式错误等）高亮并说明原因；用户确认后才写入。
- 不存在的作者自动新建，其「国家/地区归属」与「籍贯」取该行的国家与籍贯；已存在则复用。
- 文件编码兼容 UTF-8（含 BOM，即 Excel 另存的 CSV）。大小上限 2 MB。

### 7.4 完整备份与合并导入

这是电脑与手机同步的唯一通道，也是防止数据丢失的最后保险，所以放在 M1 就要做好。

- **导出完整备份**：生成 `genre-shelf-backup-YYYYMMDD-HHMM.json`，包含全部实体（含软删除的记录）和数据结构版本号。同时更新「上次备份时间」。
- **导入**：选择文件后，先显示摘要（新增 N 条、更新 N 条、删除 N 条、冲突 N 条；「冲突」指同一条记录在两边的内容都与上次不同、需要二选一的情况，默认取较新的一方，并列出供查看），选择方式：
  - **合并**（默认）：按 `id` 匹配（国家条目按 `code`）。同一 `id` 取 `updated_at` 较新的一方；一方带 `deleted_at` 且更新，则该记录视为已删除；本机没有的记录新增。
  - **覆盖**：用文件整体替换本机数据。
  - 无论哪种，**写入前都先自动导出一份当前数据**作为后悔药。
- **作者重名**：不同 `id` 但同名的作者，导入时提示「是否合并为同一人」，选是则把书籍的作者引用改指向保留的那一位。
- **书籍编号**不存储，合并后自动一致，无需处理冲突（§4.2）。
- **数据文件自动存档**（仅电脑上的 Chrome/Edge）：见 §8.2。

## 8. 数据保存、备份与多设备

### 8.1 本机存储

- 数据存在浏览器的 IndexedDB 里。启动时请求「持久化存储」（`navigator.storage.persist()`），降低被浏览器自动清理的概率。
- **不同浏览器、不同文件位置下，本地文件的存储行为不完全一致**（例如换了文件存放路径，或换用另一个浏览器，看到的可能是另一份空数据）。因此不能只依赖浏览器内部存储，见 §8.2、§8.3。

### 8.2 数据文件自动存档（电脑 Chrome / Edge）

- 设置页「绑定数据文件」：选择一个位置保存 `.json` 文件。此后每次修改，约 2 秒内自动写入该文件。
- 应用打开时，如果数据文件比浏览器里的数据新，提示「是否从数据文件加载」。
- 浏览器可能要求每次打开后重新授权，点一下确认即可。
- 手机（安卓 Chrome）不支持该功能，靠手动备份。

### 8.3 手动备份与提醒

- 设置页和表格页顶部常驻显示「上次备份：N 天前」。
- 距上次备份超过 7 天且有改动时，打开应用即提醒；一次点击完成导出。
- 清除浏览器数据、换电脑、换浏览器后，用备份文件可完整恢复（验收项，见 §13）。

### 8.4 隐私与访问

- 数据只存在本机，应用运行时不发起任何网络请求，没有统计或广告脚本。
- 没有登录与口令：谁能打开这台设备上的这个浏览器，谁就能看到数据。需要保护时，请用设备本身的锁屏。（应用内口令 v1 不做。）

### 8.5 未来扩展（不在本版范围）

云同步与多用户。数据层已预留：ULID、`updated_at`、`deleted_at`，合并规则与 §7.4 一致，所以以后加同步服务只是把「手动导出导入」变成自动。

## 13. 验收要点

1. 录入读过的书后，对应国家在地图上变色，且颜色随数量按 §5.2 规则变化。
2. 构造测试数据：一个国家 50 本，其余国家 1、2、3、4 本。后者之间在地图上颜色肉眼可分。
3. 悬停（桌面）或点按（手机）国家，面板列出作者与书；作者可折叠；顺序按本数降序；类型图标颜色与简称正确；点击书名进入详情页。
4. 地图可缩放到能点中卢森堡、新加坡、梵蒂冈等小国。
5. 录入一本归属「南斯拉夫联盟」的书，塞尔维亚、黑山、科索沃均出现颜色；苏联在无书时没有任何色块被着色。
6. 录入多本大中华作品，世界地图上大陆、台湾、香港、澳门**同一颜色、同时高亮、同一个面板**；国家下拉里**没有**单独的中国/台湾/香港/澳门选项。
7. 界面任何位置（面板、下拉、图例、详情页）**不出现国旗**。
8. 给大中华作品填写籍贯后，二级地图上对应省级单位变色；颜色在 34 个单位内部独立按 §5.2 计算；未填籍贯的书出现在「未填写籍贯」提示里，补填后消失。
9. 表格可按任意字段（含籍贯）筛选/排序/分组，汇总行正确；保存的视图刷新后仍在。
10. `genre-shelf.html` 在 Windows 的 Chrome 与 Edge、安卓 Chrome 中均可打开；**断网时功能完整**；自动化测试中拦截全部网络请求，应用仍正常工作。
11. 导入 100 行 CSV，错误行被指出；国家填「台湾」的行被归并到大中华并补全籍贯，预览中有标注；确认后正确写入。
12. **同步演练**：电脑上录入若干书 → 导出备份 → 手机导入合并，两边一致；手机上再加一本、改一本、删一本 → 导出 → 电脑导入合并，结果正确，没有重复，也没有覆盖较新的修改；两台设备上同一本书的编号一致。
13. **灾难恢复**：清除浏览器全部数据后，用备份文件可完整恢复，所有书、作者、设置、已保存视图都在。
14. 在电脑 Chrome 上绑定数据文件后，修改一本书，数据文件在几秒内更新。

### 15.2 已验证的底图数据事实（原 R3）

数据源：Natural Earth 矢量数据，GitHub 仓库 `nvkelso/natural-earth-vector` 的 `geojson` 目录。验证时下载的文件为 `ne_50m_admin_0_countries.geojson`（约 3 MB）与 `ne_50m_admin_1_states_provinces.geojson`（约 2.3 MB）。**无需使用 10m 精度文件**（admin-1 的 10m 文件约 40 MB，不适合内联）。

**世界底图（admin-0，1:50m）**

- 共 242 个要素。用 `ISO_A2_EH` 字段作国家代码：它已为法国、挪威、科索沃（`XK`）等条目补上了 `ISO_A2` 里缺失（值为 `-99`）的代码。**不要用 `ISO_A2`。**
- 仍无代码的条目需要特殊处理：

  | 条目 | 处理 |
  |---|---|
  | Somaliland | 并入 `SO` |
  | Northern Cyprus | 并入 `CY` |
  | Siachen Glacier | 不绘制 |
  | Antarctica | 不绘制 |
  | Indian Ocean Territories、Ashmore and Cartier Islands | `ISO_A2_EH` 为 `AU`，与澳大利亚共用代码（同一代码允许多个色块） |

- 按上述规则得到 **240 个色块、236 个国家/地区代码**。
- **台湾要用 `ISO_A2_EH`**：台湾的 `ISO_A2` 值是 `CN-TW`，而 `ISO_A2_EH` 才是 `TW`。直接用 `ISO_A2` 会漏掉台湾（验证时因此得到 33 而不是 34 个单位）。
- 数据自带的 `NAME_ZH` 可作为中文名底稿，但需要人工覆盖少数条目。已确认需要覆盖的：`KP`→朝鲜、`KR`→韩国、`CD`→刚果（金）、`CG`→刚果（布）、`MN`→蒙古、`AX`→奥兰群岛、`GG`→根西岛、`JE`→泽西岛；`CN`、`TW`、`HK`、`MO` 按本规格书 §4.6 命名（中国大陆、台湾、香港、澳门，且不可直接选择）。**数据自带的 `NAME_ZH` 不得原样用于大中华四个条目。**
- 简化参数参考：量化 3e4、保留约 25% 的点，世界底图约 **865 KB**，视觉上足够；需要时可再调。

**大中华二级地图（admin-1，1:50m）**

- 50m 的 admin-1 数据里，`adm0_a3 = 'CHN'` 的要素恰好 **31 个**（省、直辖市、自治区），`iso_3166_2` 形如 `CN-AH`，可直接转成籍贯码 `GC-AH`。
- **台湾、香港、澳门不在 50m 的 admin-1 里**，要从 admin-0 取（用 `ISO_A2_EH` 筛选 `TW`、`HK`、`MO`）。三者合计 31 + 3 = **34**，与规格书 §4.6 一致。
- 简化参数参考：量化 1e5、保留约 60% 的点，约 **131 KB**。
- 因此世界与大中华两份底图合计约 1 MB，远低于 §10 的 6 MB 单文件预算。

**建议的构建脚本检查项**（与 §5.1 一致）：每个世界色块都有国家条目；每个现代国家条目都有色块；所有历史国家的 `map_codes` 都指向存在的色块；籍贯 34 项与二级地图色块一一对应。

### 15.3 其他已知注意点

- **预设类型与预设国家必须用固定 ID。** 预设书籍类型用 `type-XXXX`（如 `type-LFIC`），国家用其代码。否则电脑和手机各自生成随机 ID，合并导入时会出现重复的预设。预设数据的更新时间戳用一个固定的早期时间，保证任何用户修改都比预设新。
- **预设数据升级只补充、不覆盖**，包括用户改过的条目与软删除的条目（§4.2）。
- **单文件在 `file://` 下运行**：构建后要用 Playwright 直接打开 `file://…/genre-shelf.html` 做端到端测试，并确认 IndexedDB 可用、没有外部网络请求（§13 验收项 10）。仓库里预装的 Chromium 路径为 `/opt/pw-browsers/chromium`，不要运行 `playwright install`。
- 建议的工具链：Node 22、Vite、React、Tailwind CSS 4、Dexie 4、TypeScript、Vitest。预研时已验证这些依赖可在当前环境安装，版本以实际安装为准。

### 15.4 M0 建议的起步顺序

1. 脚手架 + 单文件构建（`dist/genre-shelf.html`），先做到「空页面双击能打开」。
2. 地图构建脚本（§15.2）与一致性检查，生成两份底图与现代国家名称表。
3. 数据层：IndexedDB 结构、预设数据、`ensureSeed`、约束校验（§4.2），配单元测试。
4. 一个「自检页」作为 M0 交付的空壳：显示版本与构建时间、数据库是否可用、预设条目数量、地图预览、持久化存储是否授予、File System Access API 是否可用（§14 R7）、外部网络请求数（应为 0）。**这个页面是给委托人在 Windows 电脑和安卓手机上各打开一次用的**，所以文案要用中文、字要大、手机上不用缩放。
5. GitHub Actions 自动构建并保存构建产物。
6. README：写清楚怎么构建、怎么测试，以及给委托人的「怎么打开这个文件」说明。
